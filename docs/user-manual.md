## 1. Getting Started

### 1.1 Signing In

1. Open the app (`http://localhost:5173` in development).
2. Go to the **Sign in** page.
3. Enter your email and password, then click **Sign in**.

If your account has two-factor authentication (2FA) enabled, you will also be asked for a 6-digit code from your authenticator app.

### 1.2 Demo Accounts

| Email | Role | Notes |
|---|---|---|
| `admin@acme.com` | Admin | Full system access |
| `hr@acme.com` | HR Manager | HR operations + payroll |
| `alice@acme.com` | Employee | Self-service only |

All demo passwords: `Password123!`

> ⚠️ Change these before using in production.

### 1.3 Creating a Company Account

1. From the sign-in page, click **Create account**.
2. Enter your company name, your name, work email, and a password (8+ characters).
3. Click **Create account**.

This creates your company workspace (tenant), an **Admin** role, and your admin account. You are signed in automatically.

### 1.4 Signing Out

Click your name in the top-right corner → **Sign out**.

## 2. Roles & Permissions

The app uses role-based access control (RBAC). Every user is assigned a role, and each role has a permission matrix covering modules × actions.

**Modules:** employees, departments, teams, attendance, leaves, payroll, roles, users, settings.

**Actions:** create, read, update, delete, approve, export.

### 2.1 System Roles (seeded)

| Role | Description |
|---|---|
| Admin | Full system access |
| HR Manager | All HR operations + payroll approval |
| HR Staff | Employee, attendance, and leave processing |
| Department Head | Department scope (default permissions) |
| Manager | Team scope (no payroll, roles, or users) |
| Employee | Self-service only (clock in/out, file leaves) |

### 2.2 Managing Roles (Admin)

Go to **Admin → Roles**.

- **View roles**: table shows name, description, type (System/Custom), user count.
- **Create a role**: click **New Role**, name it, and tick the permission matrix (per module × action, or toggle a whole module on/off).
- **Edit/delete a role**: only **custom** roles can be edited or deleted. System roles are locked.
- A role that is assigned to users cannot be deleted.

### 2.3 Assigning Roles to Users (Admin)

Go to **Admin → Users**.

- The table lists all users in your company.
- Use the role dropdown next to a user to change their role immediately.

### 2.4 How Permissions Affect the UI

- The sidebar only shows pages you have **read** access to.
- Buttons (e.g., **New Role**, **File Leave**, **Clock In**) only appear if your role allows the action.
- The API enforces the same rules — a forbidden action returns `403 Forbidden`.

## 3. Employees

### 3.1 Employee List

Go to **Employees**.

- Search by name, email, or employee ID.
- Filter by **Status** (active, probationary, suspended, on leave, resigned, terminated).
- Click **View** to open an employee's profile.

### 3.2 Creating an Employee

1. Go to **Employees → Add Employee**.
2. Fill in the details: name, email, position, department, team, employment status, salary, contract dates, emergency contacts.
3. Save.

> Employee IDs are generated by the system. Contracts, salary, and other changes are recorded in the employee's **History**.

### 3.3 Employee Profile

The detail page shows:

- **Profile** — personal and employment information.
- **Documents** — uploaded files (contracts, IDs, resumes).
- **History** — a trail of changes (status, salary, position, department).

### 3.4 Departments & Teams

- **Departments** page: create, edit, and delete departments. Supports parent/child hierarchy.
- **Teams** page: create, edit, and delete teams.

## 4. Attendance & Time Tracking

### 4.1 Clock In / Clock Out

Go to **Attendance → My Attendance**.

- Click **Clock In** when you start work, **Clock Out** when you finish.
- A **break** can be started and ended with the break controls.
- You can only clock in once per day; duplicate clock-ins are rejected.
- On clock-out the system calculates:
  - **Hours worked** (breaks excluded)
  - **Late minutes** vs. your assigned shift
  - **Undertime** and **Overtime** minutes

> If the day is a company **holiday**, the record is auto-marked as `holiday`.

### 4.2 Attendance Records

The **Attendance Records** table lists every day's clock-in/out, hours, lateness, undertime, overtime, and status for all employees.

### 4.3 Corrections

If your clock-in/out time is wrong:

1. Go to **Attendance → Corrections → File Correction**.
2. Choose the field (**Clock In** or **Clock Out**), the corrected time, and a reason.
3. Submit. It appears as **pending**.
4. A manager/HR user approves or rejects it. On approval, the attendance record is updated automatically.

### 4.4 Shifts (HR)

Go to **Attendance → Shifts**.

- Create shifts with a name, start/end time, and optional break window.
- Mark a shift **Flexible** to skip late/undertime/OT calculation.
- Assign a shift to employees with an effective-from date (optionally effective-to).

## 5. Leave Management

### 5.1 Leave Types (HR)

Go to **Leaves → Leave Types**.

- Create/edit leave types: name, code (e.g., `VL`), paid or unpaid, max days per year, monthly accrual rate, max consecutive days.
- Seeded by default: **Vacation Leave** (paid, 5/yr) and **Sick Leave** (paid, 5/yr).

### 5.2 Filing a Leave Request

1. Go to **Leaves → Leave Requests → File Leave**.
2. Pick the leave type, date range, optional half-day, and a reason.
3. Submit.

The system validates:

- You have enough balance (requested days are reserved as **pending**).
- No overlap with another pending/approved request.
- You don't exceed the type's max consecutive days.

### 5.3 Approving / Rejecting (Manager/HR)

On the **Leave Requests** page, pending requests have **Approve** and **Reject** buttons:

- **Approve** → days move from pending to **used**.
- **Reject** → pending days are returned to your balance.
- **Cancel** → the employee (or HR) can cancel while still pending; days are returned.

### 5.4 Leave Balances

Go to **Leaves → Balances** to see each employee's available, pending, and used days per leave type and year, with a usage bar.

### 5.5 Holidays (HR)

Go to **Holidays**.

- Add/edit/delete holidays.
- Mark a holiday **Regular** or **Special (non-working)**.
- Mark **Recurring** to repeat yearly.
- Holidays affect attendance (auto-`holiday` status) and payroll holiday pay.

## 6. Payroll

### 6.1 Payroll Periods

Go to **Payroll → Periods**.

1. **Create Period** — pick start date, end date, pay date, and schedule type (semi-monthly / monthly). New periods start as **draft**.
2. **Compute** — the system computes every active employee's entry: basic pay, OT, night diff, holiday pay, gross pay, SSS/PhilHealth/Pag-IBIG, withholding tax, loan deductions, and net pay. The period becomes **computed**.

Basic pay follows the schedule:
- **Monthly-salaried employees** get a fixed per-period amount — the full monthly salary for a **monthly** period, half for a **semi-monthly** period — prorated if they were hired or left mid-period. Attendance still drives OT, night-diff, and holiday pay.
- **Daily-rate employees** are paid per day worked (`daily rate × days worked`).
- Monthly government deductions (SSS, PhilHealth, Pag-IBIG) and withholding tax are split across the period's checks accordingly.
3. **Approve** (requires `payroll:approve`) — review and approve. Period becomes **approved**.
4. **Release** — generates payslips (PDF) for every employee. Period becomes **released**.

**Revert to draft** is available on computed periods if you need to change data and recompute.

### 6.2 Entries & Adjustments

Open a period to see all employee entries (searchable table with full breakdown).

- **Add adjustment** to an employee's entry (positive or negative) with a reason. The net pay updates.
- **Export CSV** downloads a bank-transfer file (employee name, bank account, amount, notes).

### 6.3 Payslips

Payslips are generated on **Release** and include earnings, deductions, and net pay.

### 6.4 Government Tables & Tax (HR)

- **Contribution Tables** — SSS, PhilHealth, Pag-IBIG brackets (per-compensation ranges, employee/employer shares, effective date).
- **Tax Brackets** — BIR graduated withholding brackets (min/max, base tax, excess rate, effective date).
- **Loans** — create employee loans with principal, amortization per period, and total periods. Active loans are deducted automatically each payroll.

> Keep these tables up to date — the payroll engine reads them directly.

## 7. Notifications

### 7.1 Bell (top-right)

- Shows an unread **badge count**.
- Click to see your **last 5 notifications**.
- Click a notification to mark it read; **Mark all as read** clears the badge.
- **View all** opens the full notifications page.
- New notifications appear in real time (no page refresh needed).

### 7.2 Notifications Page

Go to **Notifications** (or bell → View all).

- Full list with type tags and relative timestamps.
- Click a row to mark it read.
- **Mark all as read** button.

### 7.3 What Triggers Notifications

| Event | Who gets notified |
|---|---|
| Leave request filed | Approvers (roles with `leaves:approve`) |
| Leave approved / rejected | The employee who filed |
| Attendance correction filed | Approvers (roles with `attendance:approve`) |
| Attendance correction reviewed | The employee who filed |

## 8. Security & Accounts

### 8.1 Two-Factor Authentication (2FA)

API endpoints (via the UI in a future release):

- `POST /auth/2fa/setup` — generates a TOTP secret + QR code.
- `POST /auth/2fa/verify` — verifies a code and enables 2FA.
- `POST /auth/2fa/disable` — disables 2FA.

Once enabled, login requires the 6-digit code from your authenticator app.

### 8.2 Password Reset

1. On the sign-in page, click **Forgot password?**.
2. Enter your email. If the account exists, a reset token is generated.
3. Use **Reset password** with the token and a new password (8+ characters).

### 8.3 Sessions

Each sign-in creates a session (kept for 30 days). Sessions can be listed and revoked via the API (`GET /auth/sessions`, `DELETE /auth/sessions/:id`).

### 8.4 Tenant Isolation

Every company (tenant) is fully isolated. Employees, payroll, leaves, and attendance from one company are never visible to another, enforced at the database level (row-level security) and the API level (tenant comes from your JWT, never from the client).

## 9. Tips & Troubleshooting

- **"Missing permission" (403)** — your role doesn't allow that action. Ask an Admin to adjust your role (Admin → Roles → edit role → tick the module/action).
- **"Already clocked in"** — you clocked in and haven't clocked out yet. Clock out first, or file a correction.
- **"Insufficient leave balance"** — you don't have enough available days. Wait for accrual or ask HR.
- **"Overlaps an existing leave request"** — you already have a pending/approved request in that range.
- **"Period must be computed before approval"** — run **Compute** on the period first.
- **Session expired** — you'll be redirected to the sign-in page; sign in again (you stay signed in on other devices).
